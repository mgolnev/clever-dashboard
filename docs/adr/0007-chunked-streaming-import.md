# 0007. Порционная загрузка и потоковый импорт больших файлов

- Статус: Принято
- Дата: 2026-09-12

## Контекст

HTML-XLS выгрузки Битрикса размером больше 10 МБ не доходят до приложения в
Amvera: внешний reverse proxy отклоняет единый multipart-запрос раньше Fiber.
Кроме того, прежний импорт одновременно держал в памяти тело запроса, HTML DOM,
все записи и все нормализованные заказы.

## Решение

1. Файлы больше 4 МБ браузер загружает отдельными запросами по 4 МБ. Backend
   хранит части во временной сессии и перед импортом проверяет их количество и
   размер. Максимальный размер одного файла — 512 МБ.
2. Управление временными частями вынесено в независимый сервис
   `services/importupload`. Незавершённые сессии удаляются через 24 часа.
3. `ingestion` разбирает HTML-XLS токенизатором, а CSV — потоковым reader. В
   памяти одновременно находится только текущая строка и батч из 200 заказов.
4. `services/orders` сохраняет батчи подготовленными SQL-выражениями в одной
   транзакции. Первоначально транзакция заменяла всю витрину; накопительная
   семантика последующих импортов принята в [ADR-0009](0009-cumulative-order-import.md).
   Ошибка оставляет прежние данные без изменений.
5. Прежний `POST /api/import` сохранён для небольших файлов и внешних клиентов.

## Последствия

- Ограничение размера одного запроса у облачного прокси больше не ограничивает
  размер всего загружаемого файла.
- Пиковое потребление памяти не растёт пропорционально числу строк файла.
- Во время финальной обработки открыта одна транзакция обновления витрины; чтения
  SQLite остаются консистентными благодаря WAL.
- Нативный OOXML `.xlsx` не добавлен: поддерживаются форматы экспорта Битрикса
  HTML-XLS и CSV.
