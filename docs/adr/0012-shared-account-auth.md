# 0012. Общая учётная запись и серверные сессии

- Статус: Принято
- Дата: 2026-11-13

## Решение

Одна общая учётная запись из AUTH_USERNAME / AUTH_PASSWORD без регистрации,
ролей и новой схемы БД. Независимый services/auth хранит случайные 256-битные
сессии в памяти процесса; handlers/auth закрывает весь /api до регистрации
доменных маршрутов. Открыты только вход и healthcheck. При отсутствии пароля
или длине меньше 12 байт backend отказывается запускаться.

Сессия действует 12 часов, отзывается при выходе и теряется при рестарте.
Cookie HttpOnly, SameSite=Strict, Secure по умолчанию. Для локального HTTP
нужно явно AUTH_COOKIE_SECURE=false. На API выставляется Cache-Control: no-store.
Вход ограничен 10 запросами в минуту на IP соединения; заголовкам прокси не
доверяем. За общим reverse proxy этот лимит может быть общим для пользователей.
Все изменяющие запросы требуют X-Requested-With: CleverDashboard; CORS отключён.
Frontend и API обслуживаются с одного origin (dev через Vite proxy).

## Последствия

Подходит для небольшого внутреннего сервиса с одним экземпляром backend.
Реплики потребуют общего хранилища сессий. У общего аккаунта нет персонального
аудита и отдельных прав. Смена пароля и перезапуск завершают все сессии.
Пароль передаётся только в окружении backend; в браузерную сборку не попадает.
При выкладке обязательно заранее задать AUTH_PASSWORD в секретах окружения.
