# 0011. Начало истории заказов и адресная очистка старых строк

- Статус: Принято
- Дата: 2026-09-25

## Контекст

Накопительный импорт сохраняет все строки выгрузки, включая заказы с ранней
`Дата создания`, попавшие в файл из-за отбора по `Дата изменения`. Одна такая
строка расширяет общий диапазон календаря и добавляет раннюю когорту клиентов.
Повторный импорт не удаляет эти строки (ADR 0009).

## Решение

1. `ORDERS_MIN_CREATED_AT` задаёт нижнюю границу даты создания заказа. При
   наличии в файле более старой строки весь импорт отклоняется атомарно с
   указанием номера заказа. Дата изменения не заменяет дату создания.
2. Для одноразового исправления SQLite-витрины оператор дополнительно задаёт
   `ORDERS_PURGE_EXPECTED`. Перед удалением приложение сверяет точное число
   старых заказов, создаёт согласованную резервную копию через `VACUUM INTO` и
   проверяет её целостность и список старых заказов.
3. Позиции и сами старые заказы удаляются в одной транзакции. Журнал `raw_import`
   остаётся историческим следом загрузки. Если число или список кандидатов
   меняется, удаление не выполняется.
4. После успешной очистки `ORDERS_PURGE_EXPECTED` убирают из окружения;
   `ORDERS_MIN_CREATED_AT` оставляют для защиты будущих импортов.

## Последствия

- Состояние витрины соответствует выбранному началу истории; календарь и
  когортный анализ продолжают пользоваться фактическим `MIN(created_at)`.
- Смешанный файл с заказами до границы отклоняется целиком. Сотрудник исправляет
  отбор выгрузки и загружает файл повторно.
- Перед изменением продакшн-БД сохраняется полная копия в `/data`. Очистка
  доступна только для SQLite и требует точного ожидаемого числа строк.
