# 0010. Когортный retention клиентов по оформленным и оплаченным заказам

- Статус: Принято
- Дата: 2026-09-14

## Контекст

После перехода на накопительный импорт в базе появилась непрерывная история
заказов. Вкладке «Клиенты» нужен календарный когортный анализ, который отделяет
повторные покупки от обычного сравнения KPI двух произвольных периодов.

## Решение

1. Выделить независимый сервис `services/customeranalytics`, который читает
   нормализованные заказы напрямую из общей БД и не вызывает `metrics`.
2. Клиента идентифицировать по нормализованному email; если его нет — по цифрам
   телефона; если нет обоих контактов — по нормализованному имени покупателя.
3. Отдавать в одном контракте две матрицы:
   - `gross`: когорта от первого оформленного заказа, активность — любой заказ;
   - `paid`: когорта от первого заказа с `is_paid=true`, активность — только
     оплаченный заказ.
4. Поддержать две календарные гранулярности: месяц (`M0…Mn`) и квартал
   (`Q0…Qn`). Строка матрицы — период первой активности, столбец — календарный
   период относительно него. Retention — доля клиентов к размеру исходной
   когорты, а не доля заказов.
5. Агрегированный retention взвешивать по числу клиентов только среди когорт,
   которые прожили соответствующее число **полных** месяцев. Незавершённый
   последний месяц показывать в матрице, но исключать из KPI.
6. API принимает сквозные бизнес-фильтры. Период сравнения к матрице не
   применяется: когортам нужна одна непрерывная временная ось.
7. Для каждого месяца/квартала дополнительно отдавать взаимоисключающий состав
   активной базы: `new` — первая активность, `active` — активность была и в
   предыдущем периоде, `returned` — предыдущий период пропущен, но есть более
   ранняя активность.

## Последствия

- Переключение gross/paid на клиенте мгновенное: обе матрицы приходят одним
  запросом.
- Качество объединения клиентов зависит от качества email/телефона в выгрузке;
  fallback по имени может объединить тёзок только у записей без контактов.
- При длинной истории ответ растёт квадратично по числу месяцев; при горизонте
  в несколько лет потребуется ограничение окна или серверная пагинация.
