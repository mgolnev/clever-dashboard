# Импорт из Битрикса (MVP-1)

## Формат файла

Выгрузка «Заказы» из Битрикса. Поддерживаются:

- **HTML-«xls»** — фактический формат экспорта Битрикса (HTML-таблица с
  расширением `.xls`). Определяется автоматически по содержимому.
- **CSV** — UTF-8 или Windows-1251, разделитель `,` или `;` (автоопределение).

Нативный OOXML `.xlsx` не поддерживается. В интерфейсе следует выбирать
выгрузку Битрикса в XLS (HTML) или CSV.

## Большие файлы

Файлы больше 4 МБ интерфейс автоматически передаёт частями по 4 МБ, поэтому
лимит размера одного HTTP-запроса на Amvera не блокирует загрузку. Общий лимит
файла — 512 МБ. После загрузки backend потоково разбирает строки и сохраняет
заказы батчами по 200.

Импорт остаётся атомарным: новые и изменённые заказы фиксируются только после
успешного разбора и сохранения всего файла. При ошибке предыдущие данные не
меняются.

Гранулярность: **одна строка = один заказ**. Позиции товаров лежат в одной
ячейке столбца «Позиции».

## Используемые поля

| Поле выгрузки | Назначение |
|---------------|-----------|
| `Номер заказа` | Ключ дедупликации (PK) |
| `Дата создания` / `Дата изменения` | Время заказа (формат `ДД.ММ.ГГГГ ЧЧ:ММ:СС`) |
| `Сумма` | Сумма заказа (`«3 313 руб»` → `3313`) |
| `Оплачено` / `Оплаты` | Оплата и возвраты: полный возврат = вся сумма заказа; при частичном возврате последняя сумма из журнала `Оплаты` — возвращённые средства |
| `Отменен` / `Оплачен` | Флаги (Да/Нет) |
| `Статус` | Сырой статус → стадия воронки |
| `Платежная система` / `Служба доставки` | Срезы оплаты/доставки |
| `Заказ из приложения` | Канал: «Приложение» / «Сайт» |
| `Выберите свой населенный пункт` | Регион/город (`Россия, край, город`) |
| `Позиции` | Товарные позиции: `[offer_id] Название (N шт)` |
| `Цена товара` | Цены позиций (`«719 руб 503 руб»`), сопоставляются по порядку |

## Разбор позиций

Столбец «Позиции» парсится регулярным выражением
`\[(\d+)\]\s*(.*?)\s*\((\d+)\s*шт\)`. Цены берутся из столбца «Цена товара»
(разделитель «руб») и сопоставляются по индексу — соответствие 1:1 проверено на
полной выгрузке (1328 заказов → 4823 позиции, 0 расхождений).

Из названия товара извлекаются атрибуты:

- `brand` — 1-е слово (CLEVER, CLES, ЭЙС…);
- `category` — 2-е слово (Футболка, Брюки, Платье…);
- `gender` — 3-е слово, нормализуется (Мужской/Женский/Детский/Унисекс);
- `size` — последний короткий токен.

## Маппинг статусов в воронку

| Статус Битрикса | Стадия |
|-----------------|--------|
| Не подтвержден | `new` |
| Оплачен | `paid` |
| Принят / Обработан / Ожидает отправку / Собирается | `processing` |
| Отправлен | `shipped` |
| Прибыл в ПВЗ | `in_pvz` |
| Выполнен | `completed` |
| Закрыт | `closed` |
| Возврат заказа / Частичный возврат / Совершён возврат средств | `returned` |
| (флаг «Отменен» = Да) | `canceled` (приоритет) |

## Накопительный импорт и идемпотентность

`Номер заказа` служит уникальным ключом для накопительного merge:

- новый номер добавляется в `orders`;
- совпавший номер обновляется, если `Дата изменения` в файле не старше уже
  сохранённой; его позиции удаляются и записываются заново;
- более старая версия пропускается и не откатывает конечный статус;
- заказы, которых нет в новом файле, остаются в БД.

Поэтому историю можно наполнить несколькими файлами, а затем регулярно загружать
новые и изменённые заказы. Повторная загрузка не создаёт дублей. Весь файл
применяется одной транзакцией; частично обновлённая витрина не становится видна.

Результат импорта содержит `ordersAdded`, `ordersUpdated` и `ordersSkipped`.
Поле `ordersCleared` сохранено для совместимости и всегда равно нулю.

## Чистый выкуп и возвраты

Для обзора и воронки считаются три независимых итога:

- **выкуплено валово** — `Выполнен` и все статусы возврата: клиент получил заказ;
- **возвраты** — число возвращённых заказов и сумма фактически возвращённых денег;
- **выкуплено чистыми** — валовой выкуп минус полностью возвращённые заказы, а
  его сумма — валовая сумма минус полные и частичные возвраты.

Частичный возврат остаётся в чистом количестве: клиент сохранил часть заказа.
